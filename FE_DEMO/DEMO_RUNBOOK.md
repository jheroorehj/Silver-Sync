# 시연 당일 진행표

AWS 없이 동작하는 **데모 모드**(`src/lib/silverSyncApi.ts`의 `DEMO_MODE = true`)로 진행합니다.
인터넷이 끊겨도 동작합니다. AI 판정은 **간호사가 입력한 혈압·혈당·복약·관찰 소견·특이사항**을
백엔드와 같은 CDS 안전 규칙(`src/lib/demoAnalysis.ts`)으로 판정해 약 6초 뒤 의사 화면에 표시합니다.

## 1. 실행

```bash
cd FE_DEMO
npm install        # 처음 한 번만
npm run dev        # → http://localhost:3000 (사용 중이면 3001)
```

## 2. 시연 가이드 투어 (권장)

- 헤더 오른쪽 **[시연 가이드]** 버튼을 누르거나 `http://localhost:3000/?demo=true`로 접속하면, 데모 기록이 초기화되고 1단계부터 자동으로 시작됩니다.
- 화면이 어두워지고 눌러야 할 곳만 밝게 표시됩니다(펄스 링). **표시된 곳을 직접 누르거나 값을 채워야만** 다음 단계로 넘어가고, 배경 클릭·ESC로는 건너뛸 수 없습니다.
- 입력 단계는 값을 다 채워야 **입력 완료** 버튼이 켜집니다. 말풍선의 **예시 값 넣기 / 예시 문장 넣기**로 바로 채울 수도 있습니다.
- 말풍선 아래 **처음부터 · 일시정지 · 시연 종료**
  - **일시정지**: 어두운 화면이 걷히고 자유롭게 스크롤·클릭해 결과를 확인할 수 있습니다. 헤더의 **▶ 이어하기 n/14**로 멈춘 단계부터 계속합니다(✕는 종료).
  - 멈춘 사이 다른 화면으로 이동했다면, 지금 화면에 있는 가장 가까운 이전 단계부터 이어집니다(예: "의사 탭을 누르세요").

| 단계 | 할 일 | 보여주는 것 |
|---|---|---|
| 1 / 14 | 상단 간호사 탭 | 방문 간호사 현장 화면 |
| 2 / 14 | 홍영희 방문 카드 | 질환·지난 측정값이 표시된 기록지 |
| 3 / 14 | **혈압 입력** (예: 138 / 88) → 입력 완료 | 즉시 "목표 초과" 경고 |
| 4 / 14 | **공복 혈당 입력** (예: 138) → 입력 완료 | 목표(80–130) 비교 |
| 5 / 14 | 복약 "잘 드시고 계심" | 복약 순응도 반영 |
| 6 / 14 | **관찰 소견 선택** (예: 어지러움 호소) → 선택 완료 | 합병증 의심 신호 반영 |
| 7 / 14 | **특이사항 입력** (예: "2주 전부터 시야가 흐리고 눈앞에 날파리가 보인다고 함") → 입력 완료 | 자유 서술 속 증상 탐지 |
| 8 / 14 | 기록 확인 후 AI 분석 요청 | 제출 전 요약 확인 |
| 9 / 14 | 전달하고 AI 분석 요청 | 입력값을 AI 분석으로 전달 |
| 10 / 14 | 상단 의사 탭 | 결과 자동 도착 |
| 11 / 14 | (자동) 에이전트 분석 대기 | 데이터 정리 → CDS 안전 규칙 → 임상 추론 → 최종 판정 진행 표시 |
| 12 / 14 | 의사 목록의 홍영희 | 입력값 기반 판정과 근거 (예시 입력 시: 대면 권고 · 위험도 78) |
| 13 / 14 | SOAP 노트 탭 | 입력값으로 자동 작성된 진료 기록 + 진료지침 원문 근거 |
| 14 / 14 | 상단 환자 탭 | 고령 환자용 쉬운 안내 |
| 완료 | "시연 마치기" | 전체 흐름 요약 |

### 입력값에 따른 판정 (백엔드 CDS 규칙과 같은 순서)

| 판정 | 조건 | 위험도 |
|---|---|---|
| 즉시 대면 평가 | 수축기 ≥180 또는 이완기 ≥120, 혈당 ≥250 또는 ≤70, 특이사항에 흉통·호흡곤란·쓰러짐·의식 변화 | 90 |
| 대면 진료 권고 (긴급) | 당뇨 환자의 시야 흐림·날파리(비문증) | 75+ |
| 대면 진료 권고 | 혈압 130/80 이상, 어지러움·부종·숨이 참·저림 (관찰 소견 칩 포함) | 60+ |
| 대면 진료 권고 (데이터 부족) | 혈압·혈당 미입력 | 55 |
| 비대면 진료 가능 | 위 규칙이 하나도 해당하지 않음 | 25~45 |

복약 누락, 공복혈당 목표 초과, 기타 관찰 소견은 판정을 바꾸지 않고 위험도에 더해지며 근거에 표시됩니다.

## 3. 직접 시연할 때 (투어 없이)

1. 헤더 오른쪽 흐린 **↺ 아이콘(데모 초기화)** 으로 리허설 기록을 지웁니다(태블릿 폭 이상에서 보임).
2. 간호사 → 환자 선택 → 혈압·혈당 입력(필수, 빈칸으로 시작하며 +/−는 지난 측정값부터) → 복약(필수) → 관찰 소견·특이사항 → 기록 확인 → 전달.
3. 의사 탭에서 약 6초 뒤 판정이 도착합니다. 다른 값을 넣어 보면 판정과 근거가 바뀌는 것을 보여줄 수 있습니다.
4. 환자 탭: **읽어주기 · 글자 크게**, 처방전 보여주기 / 가까운 약국 / 도움이 필요해요.

> 환자 화면은 브라우저 개발자도구의 휴대폰 보기(또는 실제 휴대폰에서 `npm run dev` 주소 접속)로 보여주면 고령자용 설계가 더 잘 드러납니다.

## 고령 환자 화면 설계 포인트 (발표용)

- 한 화면에 한 가지 일만, 큰 버튼(64px 이상)과 큰 글씨(본문 20px 이상)
- 아이콘에는 항상 글자를 함께 표시하고, 색만으로 의미를 전달하지 않음
- "비대면 진료" 같은 용어 대신 "전화로 진료해요"처럼 쉬운 말
- 읽어주기(브라우저 내장 음성, 설치 불필요)와 글자 크게 버튼
- 모든 화면 같은 자리에 "처음으로" 버튼, 글자 대비 4.5:1 이상

## 4. 예상 질문 대비

- **"AI가 실시간으로 판단하나요?"** → 데모 모드는 백엔드의 CDS 안전 규칙(응급 → 긴급 대면 → 일반 대면 → 그 외, 불확실하면 대면)을 화면 쪽으로 옮겨 입력값으로 판정합니다. LLM 추론 단계는 실제 파이프라인(AWS Lambda)에만 있고, `DEMO_MODE = false`로 바꾸면 API를 호출합니다. (AWS가 켜져 있어야 함)
- 진료지침 인용문은 저장소의 `2025 당뇨병 진료지침 요약문`, `2022 고혈압 진료지침` PDF 원문 그대로입니다.
- 환자 화면(박대호 님)의 안내와 처방 약은 시연용 고정 내용입니다.
